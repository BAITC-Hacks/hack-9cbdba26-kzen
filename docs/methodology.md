# Методология расчёта заказа

## Контракт ядра

Ядро получает нормализованные `Sku`, `MonthPoint`, параметры покрытия и реализацию
прогноза. Оно не импортирует FastAPI, pandas или Excel и возвращает
`SupplierOrder -> OrderLine -> ReasonPart`. Отправки поставщику нет: результат —
только рекомендация для подтверждения менеджером.

## Нормализация

Главный ключ — код 1С. Артикул поставщика используется как вторичный ключ только
при однозначном соответствии. Для каждой позиции сохраняются единица, MOQ,
помесячные продажи и остатки, текущий остаток, резерв, свободный остаток, путь и
подтверждённые крупные накладные.

- Положительная транзакция — продажа, отрицательная — возврат.
- Отрицательный месячный итог не становится отрицательным спросом.
- Пустой остаток внутри существующей строки означает stockout.
- Если строка остатков отсутствует целиком, stockout не считается подтверждённым.
- MOQ меньше единицы или нечисловой MOQ заменяется на 1 и попадает в отчёт.
- Для IEK путь суммируется по открытым заказам; для Systeme берётся `СЭ в пути`.

## Регулярный спрос

1. Из месяца вычитается избыток подтверждённой крупной накладной. Поскольку ID
   клиента отсутствует, используется номер накладной. Событие считается крупным,
   если оно не меньше 10 медианных накладных и составляет не меньше 50% продаж
   позиции в доступной транзакционной истории.
2. Оставшийся помесячный выброс срезается до ожидаемого уровня. Сравнение идёт с
   тем же календарным месяцем других лет, чтобы не удалить сезонный пик.
3. Подтверждённый stockout компенсируется средним спросом месяцев с наличием.
4. Baseline: среднее последних 12 месяцев × устойчивый рост × сезонность месяца
   поставки. Рост ограничен диапазоном 0,5–2, сезонность — 0,3–3.
5. Единственный улучшенный вариант — экспоненциальное сглаживание; для редкого
   спроса размер продажи и интервал оцениваются отдельно.

## Потребность

```text
потребность = месячный спрос
            × (lead time / 30 + целевое покрытие)
            × (1 + страховой коэффициент)

сырой заказ = потребность - свободный остаток - товар в пути
заказ = max(0, округление сырого заказа вверх до MOQ)
```

Срочность считается по свободному остатку до прибытия, без подмены его товаром в
пути. Объяснение строится только из рассчитанных компонентов: базовый спрос,
рост, сезонность, stockout, исключённые накладные, lead time, остаток, резерв,
путь, потребность и MOQ.

## Проверки и ограничения

Синтетические сценарии проверяют влияние пути, сезонность, stockout, выброс,
клиентскую накладную, отсутствие истории остатков, MOQ и полноту объяснения.
Точность прогноза пока не заявляется: для неё нужен хронологический backtest.

Текущие ограничения: нет ID клиента, справочника lead time и резерва IEK; история
заканчивается сентябрём 2026 года; глобальная денежная сезонность не заменяет
сезонность товара в штуках.
