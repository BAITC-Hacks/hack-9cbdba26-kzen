# AGENTS.md

Контекст для Codex. Хакатон HackAlem AI, 5 часов, команда из 3 человек.
Отвечай и комментируй код по-русски, в комментариях объясняй «почему», а не «что».

**Читай вместе с этим файлом:**
- `CASE.md` — кейс, структура данных, ловушки в файлах, формула расчёта. Главный документ.
- `README.md` — архитектура, команды, контракт артефакта.

## Задача

Сервис считает рекомендованные заказы поставщикам для ТОО «Электрокомплект»:
история продаж и остатков из Excel → расчёт потребности → список заказов
по поставщикам с обоснованием каждой строки → проверка и утверждение человеком.

Это **расчётное ядро, а не ML**: статистика, сезонность, тренд, выбросы, MOQ.
Обучать модель не нужно и времени на это нет.

## Что уже готово (не переписывать)

FastAPI на чистой архитектуре (`domain` → `application` → `api`, адаптеры в
`infrastructure`), три реализации модели, кэш и хранилище с fallback, 36 тестов,
Docker с профилями, замеры латентности. Прежде чем создавать файл — проверь,
нет ли подходящего.

## Жёсткие правила

1. `domain/` не импортирует фреймворки: ни FastAPI, ни pandas, ни CatBoost.
2. Роутер не содержит логики кейса — она в use case.
3. Эндпоинты с тяжёлым расчётом объявляй через `def`, не `async def`.
4. Все числа в обосновании приходят из расчёта. LLM формулирует, но не считает.
5. Заказ не уходит поставщику без подтверждения человека — это запрет из ТЗ.
6. Новая абстракция — только при второй реализации.
7. Никаких новых тяжёлых зависимостей.
8. Секреты только в `.env` (в `.gitignore`).

## Команды

```bash
make test     # тесты
make lint     # ruff
make api      # сервис на :8000/docs
make deploy   # выкатка на сервер
```

Тесты и линтер после каждого заметного изменения, не в конце.

## Порядок работы

Парсинг Excel — самая трудоёмкая часть, начинай с него и покрывай тестами:
шапки многоуровневые, имена файлов в cp437, знаки количества перевёрнуты.
Подробности в `CASE.md`, раздел «Ловушки в данных» — прочитай до первой строки кода.

Must have из ТЗ сформулированы как проверки. Реализуй их как автотесты сразу,
а не в конце: они же станут экраном «Самопроверка» для жюри.

## Стиль

Коротко и по делу. Не переписывай рабочий код ради красоты. Предлагаешь компромисс —
назови цену: что теряем по времени, качеству или простоте. Видишь, что запрос
ломает правила выше или уводит от заморозки — скажи прямо, а не выполняй молча.
