# Электрокомплект — сервис поддержки решений закупщика (прототип)

Прототип интерфейса и расчёта для кейса HackAlem AI: по складу «Алматы» и выбранной категории рассчитать регулярную потребность, предложить заказ по каждому артикулу, сгруппировать по поставщикам (Systeme Electric, ИЭК), объяснить расчёт, дать менеджеру изменить количество, утвердить версию и экспортировать.

## Запуск

Откройте `prototype_source.dc.html` в браузере (нужен доступ в интернет для шрифтов и библиотеки SheetJS). Сервер не требуется.

1. **01 Данные и параметры** — загрузите .xlsx по каждому источнику, проверьте сопоставление колонок, нажмите «Импортировать Systeme Electric / ИЭК». Без загрузки работает демо-набор (синтетика).
2. **02 Рекомендации** — поиск, фильтры, сортировка по сроку дефицита, «что если», тренды по категориям.
3. **03 Объяснение SKU** — история и прогноз, поправки спроса, остатки и поступления, пошаговая арифметика, ручная корректировка.
4. **04 Проверка и экспорт** — утверждение версии, экспорт по поставщику (CSV/XLSX, разделитель, кодировка, колонки).
5. **05 Проверки ТЗ** — сценарии приёмки, backtest, участие источников.

## Процесс и роли

- **Менеджер закупа** корректирует и отправляет версию на согласование.
- **Руководитель закупок** утверждает или возвращает на доработку с комментарием.
- Любая правка возвращает версию в черновик; правка после утверждения создаёт новую версию.
- Утверждённые версии хранятся (до 10) со снимком строк; любую можно сравнить с текущим списком.
- Журнал фиксирует версию, действие, роль и время. Сессия (параметры, правки, журнал, версии) сохраняется в браузере; импортированные выгрузки после перезагрузки нужно загрузить заново. «Сбросить сессию» очищает только данные прототипа.

## Методология

Порядок: нормализация единиц и типов документов → регулярные продажи без подтверждённых разовых сделок → компенсация подтверждённых stockout → прогноз с сезонностью и приростом → потребность на горизонт защиты → вычитание свободного остатка и поступлений → правила количества → объяснение.

- **База спроса** — среднее за последние 6 полных месяцев (текущий месяц неполный и в базу не входит). `н/д` (позиции не было) и `0` (не было продаж) различаются.
- **Горизонт** H = L + R; L и R задаются по поставщику и могут быть переопределены для позиции.
- **Сезонность**: ручной ввод по SKU → правило категории → коэффициент бренда (из файла сезонности) → 1,00.
- **Прогноз на H** = дневной спрос × H × сезонный коэффициент × (1 + прирост).
- **Страховой запас** = дни по правилу категории × дневной спрос.
- **Потребность** = max(0, прогноз + страховой − свободный остаток − поступления с ETA ≤ H). Резерв уже вычтен из свободного остатка и повторно не вычитается.
- **Заказ** = k × ceil(max(потребность / коэффициент единиц, m) / k), где m — минимум, k — кратность. Без подтверждённого MOQ или коэффициента единиц заказ не рассчитывается (статус «нужны данные»), а не заменяется догадкой.
- **Срочность** — когда кончится запас с учётом поступлений по датам; поставка внутри H, но после исчерпания, помечается как ранний риск.
- **Избыточный запас** — остаток и путь превышают потребность на H более чем на 2 месяца спроса.

### Исключение выбросов (разовые сделки)

- Порог = коэффициент (по умолчанию 3) × медиана месячных продаж.
- Документ с количеством ≥ порога — кандидат в разовую сделку.
- Документы одного обезличенного клиента в пределах двух соседних месяцев, суммарно ≥ порога — клиентская серия.
- Регулярный клиент, у которого каждый документ ниже порога, остаётся в спросе.
- Исключение не удаляет исходные строки; менеджер может вернуть сделку в спрос, действие пишется в журнал.

### Stockout

Поправка применяется только к подтверждённым периодам: продажи ÷ доля доступности. Нулевой остаток на начало месяца — только кандидат, применяется после подтверждения менеджером.

### Тренд

Прирост задаётся с источником (аналитик, менеджер). Дополнительно показывается оценка по истории — наклон Тейла–Сена (медиана попарных наклонов), устойчивый к единичным всплескам; поправка на сезон в ней не делается.

### Backtest

Скользящее окно без заглядывания в будущее. Три модели прогнозируют месяц по 6 предыдущим: (A) среднее сырых продаж, (B) среднее регулярного спроса, (C) B с трендом Тейла–Сена, оценённым только по прошлым месяцам. Цель — регулярный спрос месяца. WAPE, MAE и bias считаются отдельно по каждой единице измерения; месяцы со stockout исключены.

## Импорт выгрузок

Файлы читаются в браузере. Колонки определяются по заголовкам и правятся вручную. Правила:

- продажи — код 1С + диапазон месячных колонок (берутся последние 12, последний считается неполным);
- детализация — кандидаты в разовые сделки; «Заказ покупателя» и «Приходная накладная» пропускаются; отрицательные строки собираются как возвраты по месяцам. Флажок «Месячные продажи уже за вычетом возвратов» определяет, как их совместить с месячным файлом; дальше действует правило «Возврат»;
- товар в пути — поступления по датам, при наличии свободный остаток, резерв, категория, цена («СС реал» ценой не считается);
- справочник MOQ — кратность и минимум; нечисловые значения (`#N/A`) остаются без условия. Для ИЭК смысл «Мин. разр. к отгр.» подтверждает менеджер;
- остатки по месяцам — только кандидаты в stockout;
- сезонность — строка из 12 коэффициентов (январь–декабрь), приводится к коэффициенту месяцев горизонта H.

## Ограничения

- Демо-набор синтетический. Реальные в интерфейсе только объёмы и показатели качества выгрузок из отчёта по данным.
- Нет client_id, цен и точных stockout-интервалов в реальных выгрузках; ИЭК без снимка свободного остатка на 22.09.2026.
- L, R, правила категорий, порог разовой сделки и правило возвратов — предположения до согласования с партнёром.
- Формат импорта в 1С не согласован. Экспорт настраивается (CSV/XLSX, разделитель, UTF-8 / Windows-1251, набор колонок), но требует сверки с образцом.
- Автоматической отправки поставщику нет; экспорт доступен только для утверждённой версии.
- Разбор больших выгрузок в браузере — для демонстрации; в продукте импорт выполняется на сервере.
